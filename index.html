Attribute questions / direct answers

How the controls
work together.

Open an attribute tab to understand what it controls, where it runs, and how it contributes to a complete SASE architecture.

ZTNAHow does Zero Trust Network Access replace a traditional VPN?

ZTNA connects an authenticated user to a specific application instead of placing the device broadly on the network. Identity, device posture, location, and risk are checked before access and throughout the session.

Least privilegeApplication-level accessContinuous verification
SWGWhat does a Secure Web Gateway inspect?

An SWG evaluates web requests, destinations, files, and encrypted sessions against malware, acceptable-use, and data-protection policy at the service edge nearest the user.

URL controlThreat preventionTLS inspection
CASBHow does CASB govern cloud application use?

CASB discovers sanctioned and unsanctioned SaaS use, applies controls to sensitive actions, and combines application context with identity and data classification.

SaaS discoveryApp governanceData context
FWaaSWhy deliver firewall policy as a cloud service?

Firewall as a Service gives users, branches, and cloud workloads the same stateful controls without deploying and maintaining a separate appliance stack at every location.

Unified rulesElastic capacityGlobal enforcement
DLPWhere does Data Loss Prevention apply policy?

DLP classifies sensitive content and controls its movement across web, SaaS, private applications, and managed or unmanaged devices from the same inspection path.

ClassificationInline controlsConsistent policy
SD-WANHow does SD-WAN contribute to SASE?

SD-WAN measures available transports and selects application-aware paths into the service edge. SASE adds the shared security, identity, and data controls that follow that traffic.

Definition and context

SASE, Zero Trust,
and SD-WAN.

SASE

The cloud-delivered architecture that converges networking and security.

Zero Trust

The access principle: verify explicitly and grant only the access required.

SD-WAN

The networking capability that selects efficient application-aware paths.

Cloud-native framework

The architecture
under the architecture.

Each layer reinforces the next. Together they create a service edge that can scale globally while preserving consistent policy.

01Distributed points of presence

Place inspection and access close to users and applications, reducing latency and regional dependency.

02Unified security stack

Combine web, firewall, access, threat, and data controls in a shared single-pass engine.

03Context-aware access control

Use identity, device health, behavior, data sensitivity, and location in every policy decision.

04Integrated networking and security

Let path selection and security enforcement share application context and performance telemetry.

05Global network fabric

Carry traffic across a managed backbone with resilient routing between service edges and applications.

06Application-aware routing

Select paths by real-time health and application requirements rather than static network topology.

07Edge-based processing

Inspect and enforce close to the source while centralizing policy—not traffic.

08Encrypted traffic inspection

Apply consistent controls to encrypted sessions with policy-driven exceptions and privacy safeguards.

09Continuous verification

Reassess trust throughout a session as identity, device, and behavior signals change.

10Microsegmentation

Limit lateral movement by separating applications, workloads, and user groups through explicit policy.

11Single policy engine

Express intent once and distribute it globally with consistent interpretation and change history.
