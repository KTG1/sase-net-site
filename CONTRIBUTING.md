# Contributing

Thanks for helping improve SASE.Net.

## Before making a change

1. Open an issue or describe the intended change clearly.
2. Keep edits focused on one concern: content, visual design, accessibility, or interaction behavior.
3. Do not introduce a framework or package dependency unless it materially improves the project and is agreed in advance.

## Local review

Serve the repository locally:

```bash
python3 -m http.server 8000
```

Before submitting a change, check:

- Desktop and mobile layouts
- Navigation, tabs, accordions, and form states
- Keyboard focus order and visible focus styles
- Reduced-motion behavior
- Browser console errors
- Internal links and section anchors
- Claims, statistics, testimonials, and attribution for accuracy

## Commit guidance

Use a short, action-oriented commit message, for example:

```text
Improve mobile navigation spacing
```

Include screenshots for visible design changes and explain any content-source or accessibility decisions in the pull request.
